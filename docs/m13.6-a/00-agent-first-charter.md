# M13.6-A Agent-first Web Charter

> 关联方案：[M13.6 Agent-first Web 增强方案](../m13.6-agent-first-web.md)。本章程定义 Web 的产品边界与验收准则；实现细节以关联方案及既有稳定接口为准。

## 范围

M13.6 的 Web 是研究上下文的阅读与协作界面。它负责：

- 感知关注对象的变化；
- 阅读研究对象及其上下文；
- 解释状态、关系、验证、发现与质疑；
- 追溯到精确的 revision、事件、策略和证据；
- 生成可分享的、可定位的研究上下文；
- 发起到用户 Agent、CLI、MCP 或 SDK 的结构化 handoff。

Web 可以提供手动提交入口，但复杂 Web 表单不是主要交互。主操作应优先生成明确意图、稳定对象标识和可继续执行的 handoff。

## 用户承诺

用户在 Web 中看到的是可阅读、可解释、可追溯、可分享的研究记录，而不是替用户做出研究判断的黑箱。

当用户需要创建、更新或编排结构化研究数据时，EviMesh 优先支持其通过 CLI、MCP、SDK 或用户自有 Agent 完成；Web 会保留可访问的手动提交回退路径，服务于无 Agent、无障碍和故障回退场景。

## 决策规则

1. **读优先，写交接优先。** Web 的默认职责是感知、阅读、解释、追溯、分享与发起 handoff；结构化写入的主要通道是 CLI、MCP、SDK 和用户 Agent。
2. **保留回退，不反客为主。** 手动 Web 提交必须可访问且可用，但不应成为复杂研究录入或编排的首要路径。
3. **不设平台通用聊天 Agent。** 平台不拥有或运营一个替代用户 Agent 的通用聊天 Agent；Web 只协助用户把明确上下文交给其选择的执行通道。
4. **不把证据压缩成真假分数。** 不提供标量的“真相分”“支持度分”或等价排名；展示可追溯的状态、证据关系、验证结果、独立性、发现与质疑。
5. **不强迫树形叙事。** Question、Claim、Evidence 及相关对象保持既有 DAG 和 revision 语义，不强制为 Question → Claim → Evidence 的单父子树。
6. **不替换既有写入通道。** 不删除、不复制、不降级 CLI、MCP、SDK 的能力或接口；Web handoff 应引用并延续这些通道，而非另造平行协议。
7. **精确上下文可带走。** 每次 handoff 和分享都应尽量携带稳定对象 ID、revision、当前视角与永久链接，同时不得包含凭据或敏感 payload。

## 非目标

- 把 Web 建成通用研究聊天产品或平台自有 Agent；
- 以复杂表单替代 Agent、CLI、MCP 或 SDK 的结构化写入体验；
- 用证据数量、颜色或单一标量替代可解释的研究状态；
- 将多关系、可修订的研究图谱扁平化为强制树结构；
- 移除、重复实现或迁移既有 CLI/MCP/SDK 能力。

## 退出证据

M13.6-A 可退出时，应能提供以下可检查证据：

- Web 页面和交互明确以读取、解释、追溯、分享与 handoff 为主；
- 对复杂写入任务，默认操作生成或展示可执行的 CLI/MCP/SDK/用户 Agent handoff，而非引导至主流程中的复杂表单；
- 手动 Web 提交入口仍可访问，且被定位为回退路径；
- 界面与文案不存在平台通用聊天 Agent、标量真相分或支持度分的产品承诺；
- 研究关系可按既有 DAG、revision 和可追溯语义浏览，未被强制重塑为 Question → Claim → Evidence 树；
- CLI、MCP、SDK 仍是可用的主要结构化写入通道，未被删除、复制或降级；
- handoff 与分享可定位到对应研究上下文，且不泄露凭据或敏感数据。
