    颜色语言

    三层 token（primitive → semantic → component）与协议语义色的单一事实源。所有 fg/bg 组合已在亮/暗双主题下通过 WCAG 2.2 AA（文本 ≥4.5:1）计算校验。颜色只表达含义，不做装饰。

    Primitive Semantic 状态双档 协议语义映射 DAG 边编码 序列色 对比度自检

    Primitive（原始色阶）

    5 族 · 60 阶

    原始色阶只供 semantic 层引用，组件禁止直接使用。中性色 hue 255（蓝灰），状态色相：success 152 / warning 75 / danger 27 / info 240，品牌 hue 258。

    Semantic（语义 token）

    surface · fg · border · action

    语义 token 是组件唯一应引用的颜色来源；暗色模式通过同名 token 换值实现（非反色）。每个色块同时标注用途。

    状态色双档（muted 底 / emphasis 实底）

    每个状态角色提供「muted 浅底 + 同色 fg」用于徽标与信息条，另提供「emphasis 实底 + onEmphasis 文字」用于最关键的单一状态。徽标永远是「文本标签 + 底色 + 可选图标」，颜色不是唯一载体。

    协议语义色映射

    claim · evidence · finding · change

    把 EviMesh 协议状态映射到双档状态色。映射只决定「用哪档颜色 + 哪个徽标」，不引入新颜色。

    Claim 状态（状态机 10 态）

    主推进链 hypothesis → candidate → under_verification → provisionally_accepted → accepted；任何阶段都可进入 contested / refuted / superseded / retracted / dependency_tainted。

    hypothesis candidate under_verification provisionally_accepted accepted contested refuted superseded retracted dependency_tainted

    Evidence 链接与 Verification outcome（共用 4 类语义）

    supports refutes qualifies reproduces inconclusive

    徽标只说明关系方向与性质；数量与强度通过分组计数与可追溯链接呈现，绝不换算为分数。

    Finding severity（4 级）

    critical major warning note

    Change level（4 级，仅注意优先级，不表真伪）

    critical attention update quiet

    Challenge 状态（open → admissible → investigating → upheld / rejected / resolved）

    open admissible investigating upheld rejected resolved

    DAG 边编码（14 种 Claim→Claim 关系）

    边用「颜色族 + 线型 + 关系标签」三重编码，颜色永不单独承载语义。5 个颜色族 × 线型覆盖 14 种关系；每条边在图上带可读 relation 标签，图例固定如下。

    positive negative qualify structural lineage
    颜色族线型关系（relationType）
    positive实线supports, reproduces, verifies
    negative实线加粗refutes, contradicts, challenges
    qualify虚线qualifies
    structural点线depends_on, uses_method, uses_dataset, implements
    lineage点划线extends, supersedes, derived_from

    数据可视化序列色

    8 色

    低饱和、中等明度的 8 色分类序列，相邻色相差最大化。序列色不映射语义（禁止「红=坏」式捷径）；含义永远来自文本标签。用于角色分布、贡献聚合等纯分类场景。
